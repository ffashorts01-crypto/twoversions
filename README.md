# Сравнение освещения войны — v2 (SEO-статический многоязычный сайт)

Пересборка прототипа `/workspace/compare-site` (v1 не тронут). 24 карточки, написанные вручную (`src/cards.py`), **плюс карточки, создаваемые автоматически**
конвейером `update.py` (сбор → кластеризация → фильтр релевантности → пересказы → проверки в коде → переводы → шкала подтверждённости → ворота качества → сборка сайта) без ручной проверки.
Отдельная страница на каждое событие с читаемым URL, три языка (**/ru/, /uk/, /en/**), страницы по регионам и датам, «О проекте» (методика, шкала, прогноз ошибок, политика исправлений),
публичный «Журнал исправлений», sitemap с hreflang, JSON-LD, Open Graph и т. д. Без внешних фреймворков на стороне сайта, один CSS, два необязательных маленьких JS (фильтры, переключатель темы).

## Быстрый старт
```
cd /workspace/compare-site-v2
python3 build.py                      # сборка (+ проверка цитат + проверка HTML/ссылок/sitemap) -> public/
python3 -m http.server 8089 --bind 0.0.0.0 --directory public     # локальный просмотр
```
Нужен только Python 3 (стандартная библиотека). Сборка падает (exit 1), если хоть одна цитата не является **дословной подстрокой**
сохранённого текста статьи нужной группы (та же проверка, что в v1), если нет перевода карточки/тега или если проверка выдала проблемы.

## Автообновление: `update.py`
Одна команда (годится для cron / GitHub Actions). Нужен Python 3.10+, `pip install -r requirements.txt` (в `.venv` уже стоит) и ключ LLM в окружении (в логи не попадает): по умолчанию `LLM_PROVIDER=qwen` + `DASHSCOPE_API_KEY` (Alibaba Cloud Model Studio, OpenAI-совместимый endpoint `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`, меняется `LLM_BASE_URL`); запасной вариант `LLM_PROVIDER=openai` + `OPENAI_API_KEY`.
```
cd /workspace/compare-site-v2
.venv/bin/python update.py                 # полный инкрементальный прогон: собрать новое -> кластеры -> карточки -> экспорт -> build.py
.venv/bin/python update.py --dry-run       # ничего не пишет, не вызывает LLM: сколько статей/пачек/событий было бы обработано
.venv/bin/python update.py --skip-collect  # без сбора (только LLM-этапы + сборка)
.venv/bin/python update.py --sources meduza,dw --skip-llm --no-build     # собрать только эти источники
.venv/bin/python update.py --sources ria --backfill-since 2026-10-01 --skip-llm --no-build   # пересканировать источник с даты
.venv/bin/python update.py --budget 7 --run-budget 2       # жёсткие лимиты расходов (USD)
```
Коды выхода: 0 — успешно, 1 — другой запуск идёт / нет ключа, 2 — не прошла сборка/проверка сайта, 3 — достигнут лимит бюджета (частичный результат сохранён и опубликован).
Идемпотентность: известные URL не скачиваются повторно; статья принадлежит ровно одному событию; карточка пересчитывается только если изменился набор релевантных статей (хэш входа); повторный запуск без новых данных не тратит деньги на LLM.

**Бюджет (~30 $/мес на GitHub Actions).** Каждый вызов LLM записывается в таблицу `llm_usage` (токены из поля `usage` ответа × цены в `pipeline/common.py`). Жёсткие капы: `LLM_DAILY_BUDGET_USD` (по умолчанию **1.0** $/сутки Europe/Berlin), `LLM_RUN_BUDGET_USD` (по умолчанию **0.45** $ за запуск), плюс lifetime `LLM_BUDGET_USD`. Перед вызовом оценивается стоимость; если кап был бы превышен — вызов не делается, код выхода 3. Кластеры сортируются по важности (`pipeline/importance.py`: обе стороны ru+ua, независимые СМИ, удары/потери/территория/дипломатия/оружие/НАТО); при нехватке бюджета мелкие односторонние откладываются. Модели по умолчанию (Qwen): `qwen3.7-flash` (массовые шаги), `qwen3.7-plus` (трудные случаи), режим thinking выключен; для OpenAI — `gpt-6-luna` / `gpt-6.1-sol`. Переопределяются `MODEL_BULK`/`MODEL_HARD`; цены (с ценовыми ступенями по длине запроса) — `PRICES` в `pipeline/common.py`.

**Расписание (cron).** Каждые 3 часа, с блокировкой повторного запуска (внутри уже есть `flock` на `data/update.lock`):
```
17 */3 * * *  cd /workspace/compare-site-v2 && DASHSCOPE_API_KEY=... BASE_URL=https://example.org CONTACT_EMAIL=real@address LLM_BUDGET_USD=10 .venv/bin/python update.py >> logs/cron.log 2>&1
```
Сайт (`public/`) пересобирается в конце каждого запуска; веб-сервер/туннель менять не нужно. GitHub Actions: заготовка в `deploy/update.yml.example` (состояние `data/` нужно хранить между запусками — кэш/артефакт/ветка).
Логи: `logs/update.log` (все запуски), статистика запусков и источников — в `data/articles.db` (таблицы `runs`, `source_log`, `llm_usage`).

### Конвейер (модули `pipeline/`)
| этап | модуль | что делает |
|---|---|---|
| сбор | `collect.py` | инкрементально, пауза на хост, проверка robots.txt, источник → `articles`; поле `military` по ключевым словам |
| кластеры | `cluster.py` | Luna, пачки ≤100 статей + названия недавних открытых событий (E…/H… для 24 ручных карточек); проверка id (повторы, пропуски → отдельный запрос, чужие id), 2 прохода; проход слияния разбитых событий |
| релевантность | `relevance.py` | «описывает ли статья именно это событие?» (yes/partial/no); только «yes» попадают в пересказ |
| карточки | `summarize.py`, `checks.py`, `translate.py`, `cards.py` | пересказы по группам + расхождения + цитаты (Luna; на Sol — при числовых расхождениях, ≥9 статьях или после неудачной проверки); проверка дословности цитат, привязки чисел к источникам, перевода uk/en; ворота качества |
| названия | `places.py` | проверка в коде, что топонимы (справочник GeoNames UA+RU, `data/gazetteer.json.gz`, пересобирается `tools/build_gazetteer.py`) и фамилии из русского оригинала есть в переводе uk/en; при расхождении — один повторный перевод с подсказкой написаний, затем перевод (и карточка) не публикуется; журнал `logs/place_names.log` |
| шкала | `confidence.py` | метка и индекс подтверждённости из признаков (считается в коде) |
| хранилище | `articles.db` → `data/cards_auto.json` | `cards_auto.json` — экспорт (опубликованные и отклонённые карточки с причинами) — его читает `build.py`; `data/corrections.json` — журнал исправлений |

**Ворота качества** (карточка не публикуется): <2 релевантных статей или <2 разных источников; фильтр подтвердил <50% статей кластера; у стороны с пересказом нет проверенной цитаты; ≥2 чисел из пересказа не найдены в источниках; модель сообщила `uncertainty=high`; не прошёл перевод; битый ответ. `build.py` дополнительно перепроверяет цитаты опубликованных автокарточек и **карантинит** отдельную карточку, не останавливая сборку (для 24 ручных карточек ошибка по-прежнему останавливает сборку).
Если ранее опубликованная карточка перестаёт проходить проверки или объединяется с другой, она снимается, а в `data/corrections.json` автоматически добавляется запись (`auto: true`), видимая на странице «Исправления». Исправление по сообщению читателя вносится вручную: добавить в `entries` объект `{"date":"YYYY-MM-DD","kind":"withdrawn|corrected","auto":false,"event_id":"a12","title_ru":"…","reasons":["manual"]}` (коды причин — в `src/ui2.py`, `REASON_TEXT`) и пересобрать.

## BASE_URL (важно!)
Канонические URL, hreflang, sitemap.xml, robots.txt и OG-теги строятся от `BASE_URL`. Порядок выбора:
1. флаг `python3 build.py --base-url https://example.org`
2. переменная окружения `BASE_URL=https://example.org python3 build.py`
3. самый свежий `https://….trycloudflare.com` из `tunnel.log` (временный адрес quick-tunnel)
4. `http://localhost:8089`

> **Перед публикацией на реальном домене обязательно пересоберите с настоящим `BASE_URL`** — адрес quick-tunnel меняется при каждом перезапуске
> cloudflared, и поисковики не должны индексировать временный домен. После смены тоннеля тоже нужно пересобрать (`python3 build.py`).

Другие настройки (переменные окружения): `CONTACT_EMAIL` (адрес в ссылках mailto; по умолчанию `twoversions@proton.me`),
`PUBLISHED` (datePublished 24 ручных карточек; по умолчанию 2026-09-30; у автокарточек — дата первой публикации). `dateModified` и `<lastmod>` — дата сборки.

## Аналитика и обратная связь
- Аналитика **выключена**. В `<head>` каждой страницы лежит закомментированный шаблон Plausible/Umami. Включить при сборке:
  `ANALYTICS=plausible ANALYTICS_DOMAIN=example.org python3 build.py` или
  `ANALYTICS=umami ANALYTICS_SRC=https://umami.example.org/script.js ANALYTICS_ID=<uuid> python3 build.py`.
- Обратная связь — `mailto:` (`twoversions@proton.me`, меняется через `CONTACT_EMAIL`) в футере и под каждым событием; в письмо подставляется URL страницы.

## URL-схема
```
/                              выбор языка (JS: редирект по localStorage / языку браузера; без JS — три ссылки)
/{lang}/                       список событий (фильтры по охвату/региону/дате/поиск — JS, без JS виден полный список)
/{lang}/YYYY-MM-DD-slug/       страница события, напр. /ru/2026-09-30-kharkiv-krysha-devyatietazhki/ (дата = начало периода события)
/{lang}/region/  /{lang}/region/{region}/     регионы (12)
/{lang}/date/    /{lang}/date/YYYY-MM-DD/     архив по датам (события отнесены к дате начала периода)
/{lang}/about/                 «О проекте»: методика, шкала подтверждённости, прогноз ошибок, политика исправлений, нейтральность, анонимность, источники, контакты
/{lang}/corrections/           публичный журнал исправлений + сводка автоматических отказов в публикации
/sitemap.xml  /robots.txt  /404.html  /assets/…
```
Slug одинаков во всех языках, меняется только префикс. Slug-и заданы вручную в `src/events.py`.

## SEO-чеклист (что реализовано)
уникальные `<title>` и `meta description` на каждой странице; `<link rel=canonical>`; `<html lang>`; hreflang ru/uk/en + x-default (взаимные);
Open Graph + Twitter Card (одна общая картинка 1200×630); JSON-LD: `NewsArticle` (события), `WebSite` (главные), `BreadcrumbList`, `CollectionPage/ItemList`, `AboutPage`;
`sitemap.xml` с `xhtml:link`; `robots.txt`; семантическая вёрстка (`h1/h2`, `article`, `section`, `nav`, `time`, `blockquote lang=`); адаптивный CSS, тёмная тема; ссылки «предыдущее/следующее событие» и «другие события региона».

## Проверка
`python3 build.py` в конце запускает `tools/check.py`. Отдельно: `python3 tools/check.py public https://BASE`, `python3 tools/check.py --http http://localhost:8089`.

## Туннель (временный публичный адрес)
```
cd /workspace && (setsid nohup bin/cloudflared tunnel --no-autoupdate --url http://localhost:8089 > /workspace/compare-site-v2/tunnel.log 2>&1 &)
# дождаться строки https://….trycloudflare.com в tunnel.log, затем:
cd /workspace/compare-site-v2 && python3 build.py
```

## Известные ограничения
- Переводы на украинский и английский — машинные (LLM) и не вычитаны человеком; русский — оригинал. Пересказы (во всех языках) автоматические; цитаты проверяются, пересказы — нет.
- Пересказы, расхождения, шкала подтверждённости и переводы автокарточек создаются автоматически без ручной проверки; оценки ошибок на странице «О проекте» — по маленьким выборкам.
- RIA: `robots.txt` запрещает `/services/` (подгрузка, которой пользовался v1), поэтому читаются RSS и дневные архивы разделов — охват неполный. Глубина остальных источников ограничена тем, что отдают RSS/sitemap.
- Источники, закрытые для автоматического чтения (Reuters, Ukrinform, Коммерсантъ, Lenta — robots.txt, РБК — 401), не используются; список — на странице «О проекте» и в `pipeline/collect.py:NOT_USED`.
- Cloudflare quick-tunnel добавляет в `robots.txt` собственный блок «Managed content» (запрет ряда AI-краулеров) перед нашим и подменяет `mailto:` на `/cdn-cgi/l/email-protection`; на собственном домене этого не будет (зависит от настроек).
- `datePublished` — дата сбора данных (константа), а не дата публикации первоисточников.
- В `x-default` у внутренних страниц указана английская версия, у главных — корень `/`.
